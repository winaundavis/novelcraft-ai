# 项目对话记录与正文候选
更新：2026-09-13。

## 会话操作
项目助手顶部“对话记录”菜单提供最近对话与已归档对话。“新对话”建立独立聊天上下文，仍读取当前小说资料。首次问题作为标题，不另调用模型命名。

- 会话、消息和处理状态保存在现有 SQLite，刷新/重新进入读取已有记录。
- 归档不删除，可从已归档列表恢复继续；删除需确认，只删除会话和消息，不撤销已应用的大纲/正文。
- 回复时先保存问题和处理中状态；刷新查询结果，不重新发起模型请求。
- 后端重启会将未完成回复标记为中断；用户手动重新生成可能收费，不自动 retry。
- 候选恢复时读取最新状态，已接受/拒绝的不再次冒充待处理。

历史仅存组件内存、刷新已丢失的消息不能补回；不将来源不明的旧全局浏览器缓存分配给任意项目。

## 正文修改
作者要求改正文时，在正文区域查看生成/候选内容；对话展示修改说明与确认，不将整章作为普通聊天回答充满窗口。大纲修改与正文候选是不同操作，普通咨询不会变成“已应用”。

接受候选返回 applied_content，编辑器接收 chapter-changed/project-refresh，同步对应项目和章节；在助手独立页编辑器未挂载时，仍须使用最新正文建立下次候选。已有测试覆盖这条同步链；这不证明服务端所有派生索引已同步，待办见工作清单 T2。

编辑器有未保存修改时，先保存再接受，避免覆盖本地草稿。若候选生成后正文/版本又变，接受会发生冲突；应重新加载核对差异，不能强制套用过期候选。刷新、切会话和切章本身不得自动再调用模型。

## 权限、成本与核验
对话接口要求项目 owner 和会话所属项目（既有管理员权限例外保持）：401未登录、403非owner、404不存在/不属于当前项目、409处理中或归档等冲突。删除会话不替代数据备份或作品回收站。

默认零API验证入口（分别在 backend/、frontend/）：
```text
py -3 -m pytest tests/test_chat_conversations.py -q
npm run test:e2e -- tests/e2e/chat-conversations.spec.ts tests/e2e/copilot-accept.spec.ts --workers=1
```
前端需已启动并拦截API；后端使用临时SQLite/mock。细节见[测试隔离](test-suite-runtime.md)。
