### 3.3 难点一：AI 长文生成"质量不可控"，且**失败得很安静**

| 具体表现 | 后果 | 已落地的对策 |
|---|---|---|
| 正文被 `max_tokens` 截断，却被当成完整章节**落库** | 用户看到半章，以为生成成功 | 正文输出预算加下限；不足即判失败重试 |
| 规划角色（大纲）的推理吃光输出预算 | 大纲"必坏"，永远是残的 | 规划与写作分角色、分预算；长书大纲改**分卷生成** |
| 去 AI 味环节**静默吞掉正文** | 越润色越短甚至消失 | 幅面上界 + 台词保真校验；改动量超阈值即拒绝 |
| 大纲"每卷都是同一句模板" | 反复修 46 条目 | 卷级信号**逐卷生成**，禁止整体套模板 |
| 「一键修改」改到一半整批失败 | 前面改的全白改 | 改为逐章提交 + 断点续做 |

**根因**：LLM 的失败模式是"低质量的成功"，不是确定性的报错，`try/except` 抓不住。
**由此确立的铁律**：凡是"模型输出 → 落库"的路径，必须有**独立于模型的判定器**（长度、结构、字段、正则、二次校验），否则一律视为可疑。

### 3.4 难点二：Token 与上下文的经济问题

| 数据 | 含义 |
|---|---|
| Codex input 4.276 亿 token | 相当于把整套代码反复读上百遍 |
| 其中 cached 4.015 亿（93.9%） | 不是读得多，而是**同一堆上下文被反复重发** |
| output 仅 138.5 万 | 输入:输出 ≈ **309 : 1**，典型的长上下文空转特征 |
| 上下文压缩 59 次 | 填满 → 压缩 → 再填满，来回 59 轮 |
| 最差单会话：2026-08-29 | 171 MB / 228 条消息 / **43 次压缩**（一天内几乎每轮都在遗忘与重读） |
| Copilot 工具调用 25,259 次 | 平均每次对话约 17 次工具往返 |

**为什么会贵**：每次"读一下这个文件"，都要连带塞入历史、指令、错误日志；上下文一满就压缩，压缩丢细节，丢细节就重读——形成"重读—压缩—重读"循环。

**如何压下来**：把"反复读"换成"一次写成文档"——`AGENTS.md`、`docs/` 92 篇、CHANGELOG 分轮条目、可再生物清理。
本质是**把上下文成本从"每次重算"转为"一次沉淀"**。

### 3.5 难点三：反复被提出、反复被修的四类问题

1. **章节名与内容不匹配 / 章节名重复**（23 条目 + 51 次原话）
   早期由提示词顺手生成，无结构约束。后改为**独立建模**：AI 起名 + 作者可改 + 改名后一致性校验。
2. **字数不足 / 字数口径不统一**（30 条目）
   同一"字数"在前后端与提示词各算一遍，互相打架。2026-10-22 统一口径。
3. **世界规则"设了但不生效"**
   2026-10-22 条目原文：*"此前是部分注入 + 无人校验"*。
   **"配置项存在"不等于"配置项生效"**，这是本项目最隐蔽的一类缺陷。
4. **额度误拦正常创作**（2026-10-21）
   最终拆成两层：项目成本护栏 + **用户每日章数额度**，并加开关
   （`USER_DAILY_CHAPTER_LIMIT_ENABLED`），测试期可关闭。

### 3.6 难点四：返工循环的组织性成因

- 极短追问占 **10.1%**（105 条 ≤ 15 字）；"继续"出现 105 次、"重新"73 次、"不对"7 次、"没反应"4 次。
- 说明大量轮次不是"提需求"，而是**验收失败后的微调**。
- 三个成因：需求以口头追加形式进入、缺少成文验收标准、修一处坏一处（`2026-10-10` 条目自述"我引入的回归"）。
- 对策：把"人肉检查"换成"机器门禁"（见第四节）。

### 3.7 难点五：交付链路的"不可见性"

| 现象 | 真实原因 |
|---|---|
| 白屏 | 浏览器缓存旧 `index.html` → 请求已删除的旧 JS → SPA 回落把 **HTML 以 200 当 JS 返回** |
| 按钮看不见 | `bg-primary` / `text-danger` 在 Tailwind 配置中**不存在**，类名被静默丢弃 → 白字白底 |
| 已删除的文字又出现 | 把删除之前的构建（`stage4`）发到了生产 |
| 域名打不开 | `nip.io` 在该网络下 TLS 握手被重置 |

**共同点**：全部是"不报错的错误"。只能靠可观测性与可验证的发布流程解决。

## 四、走过的弯路

| # | 设想 | 实际情况 | 代价 | 最终路径 |
|---|---|---|---|---|
| 1 | 用免费 PaaS 托管 | SQLite 磁盘是临时的；生成 5–10 分钟超过函数超时；必须单实例 | 反复调研 | 云主机 + Caddy + systemd |
| 2 | 家里电脑开隧道 | cloudflared 52 MB 在受限网络 0.08 MB/min；匿名隧道服务已不再发 URL | 一整天 | `tunnelmole`（后亦弃用：12 小时超时、URL 每次变） |
| 3 | `nip.io` 免费域名 | 该网络下 TLS 握手被重置 | 一轮调试 | 换 `sslip.io`，staging 改名去混淆 |
| 4 | 在服务器上直接写长命令改文件 | PowerShell 5.1 的 here-string 与嵌套引号被 SSH 吞掉 | 多次改坏配置 | **一律上传 `.sh`/`.py` 脚本再执行** |
| 5 | 用脚本改 `.ps1` | BOM-less UTF-8 被 PowerShell 误判 → "字符串缺少终止符" | 反复失败 | `UTF8Encoding($true)` 写 BOM；bash 用 LF |
| 6 | 中文直接贴进终端做编辑锚点 | 终端回显乱码，锚点永不匹配 | 白折腾 | 只用文件读取获取真实内容 |
| 7 | 前端用 `bg-primary` / `text-danger` | 类名不存在，被静默忽略 | 按钮隐形，误判为"功能没做" | 改用存在的色阶，并**在构建产物 CSS 中校验类名** |
| 8 | 打包"最新"前端产物 | 打的是删除前的旧构建 | 一次返工 | 发版前校验产物 hash 与源码一致；保留上一版 assets |
| 9 | 让服务器对未知路径回落 `index.html` | 缺失的 `/assets/*.js` 也回落成 HTML（200） | 一次线上白屏 | `/assets/*` 缺失直接 404；`index.html` 走 `no-cache` |
| 10 | 认为"没配 key 也能跑 AI"是泄漏 | 实为本机 `DEEPSEEK_API_KEY` 用户环境变量生效 | 一度怀疑密钥泄漏 | 验证环境变量链路，确认非泄漏 |
| 11 | 本地测试全绿即视为 Linux 也能跑 | `e2e_report.py` 硬编码 Windows 路径，在 Linux 造垃圾目录并让打包测试失败 | 一次发版阻塞 | 改环境变量 + 临时目录 |
| 12 | 认为"匿名当管理员"是漏洞 | 这是 `DEBUG=true` 的既有设计（匿名 = `local-dev` = 管理员） | 一次误判 | 用测试钉死该行为；生产强制 `DEBUG=false` |

**共性**：12 条中 5 条（#7 #8 #9 #10 #11）属"不报错的静默失败"，这直接决定了后期工程重心。

## 五、如何克服：把"人工盯"换成"机器拦"

### 闸门一 · 静态检查（挡在提交前）
`flake8` 0 问题、前端 `tsc` 0 错误、`eslint` 0 error；另有自定义静态守卫拦截"hook 依赖放了不稳定 prop"。
门禁相关变更占 `CHANGELOG` 的 **83/100**。

### 闸门二 · 测试即契约
- 后端 1,509 用例、前端 107 单测、129 个测试文件。
- 关键是把**易错行为钉成测试**：额度开关开/关、管理员无限额、非管理员 401/403、
  `DEBUG=true` 匿名即管理员、邀请码批量生成不泄露明文、打包必须含必需文件与目录名。

### 闸门三 · 可验证的发布
- 发布包 454 文件 `SHA256SUMS` + `sha256sum -c` 全通过；`release_audit` 441 文件 0 违规。
- 发版后校验产物 hash：本地 / 服务器 / HTTP 下载三方 SHA256 一致。
- 白屏事故后新增验证：旧资源 → 404、当前资源 → 200。

### 闸门四 · 可恢复性（假设一定会坏）
- 每日 03:30 自动备份 + **真实恢复演练**（`integrity_check=ok`、外键干净）。
- provider key 加密存储与迁移；staging 独立库副本；`current` 软链回滚。
- `docs/OPS_RUNBOOK.md`：发布、回滚、备份恢复、故障速查。

### 针对"AI 不可控"的三层约束
1. **结构化上下文**：世界规则 / 人物卡 / 伏笔 / 时间线均为数据库对象，生成时强制注入**并校验确实进入了最终请求**。
2. **确定性判定器**：字数、结构、字段、截断、改写幅度全部用代码判，不交给模型自评。
3. **渐进式创作流**：大纲 → 分卷 → 章纲 → 正文 → 审校，而非一次生成全文。

## 七、可复用结论

1. **失败必须被显式判定**——凡是模型输出落库，必须有独立于模型的校验器。
2. **配置存在 ≠ 配置生效**——世界规则、额度、缓存都栽在这条上；必须断言"真的进了请求"。
3. **不报错的错误最贵**——白屏、隐形按钮、错构建产物、编码问题，只能靠门禁与可验证发布解决。
4. **上下文成本要沉淀，不要重算**——把重复的读取固化成文档与契约，比"再多读一遍"便宜一个数量级。
5. **返工的根因多半是验收标准缺失**——先写成可验证的判定条件，再开始写代码。
