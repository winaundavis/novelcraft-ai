# 章节回收站

更新：2026-10-12。

章节导航的“回收站”可查看被移除的整章正文。列表显示原始标题、卷/弧位置、字数、移除原因和时间；点击后预览完整正文。

- 在章节导航移除正文，或修改大纲导致原章节节点被移除，正文进入回收站。重新导入并替换项目正文也使用相同保护。
- 还原时从**当前大纲**选择目标章节。目标没有正文时直接还原；已有正文时需明确确认，旧正文先进入回收站，然后写入还原内容。
- 还原不改动目标章节的大纲标题、剧情弧和顺序。选择目标后若大纲或正文已被其他页面修改，操作会拒绝，需刷新后重新确认。
- 永久删除需要确认，只删除所选回收记录；不会删除当前章节或清空其他回收内容。不设自动清理期限。
- 编辑器有未保存修改时先保存；创作任务正在运行时暂不能移除或还原章节。

## 多选与批量操作

列表左侧有复选框，工具条有「全选 / 取消全选」与「已选 N 条」，选中后可一次完成：

- **一键还原所选**：每条记录各自回到**它自己的原章节**（被移除时所在的章节）。
  批量还原不提供「统一目标章节」——多份原稿塞进同一章节会互相覆盖，所以这里只有一种含义。
  需要换目标章节时，走单条还原（那条路径允许任选目标）。
- **一键删除所选**：永久删除选中的多条原稿，需二次确认（确认框会写清共几条），删除后无法恢复。

批量还原遇到下面情况会**跳过而不是覆盖**，并在结果区逐条说明原因：

| 跳过原因 | 说明 |
|---|---|
| 原章节已不在当前大纲中 | 无法自动定位目标，需单独选择目标章节还原 |
| 原章节已有正文 | 批量操作不会覆盖正文，请单独确认后再还原 |
| 同一原章节被本批多条记录指向 | 只还原第一条，其余留给作者单独处理 |
| 记录已不存在 | 可能已在别处被还原或删除 |

还原成功的记录会从选择中移除；**被跳过的仍保留选中态**，方便作者接着逐条处理。
批量还原与批量删除同样受「编辑器有未保存修改」和「创作任务运行中」两条前置条件限制；
大纲已变化时整批**零改动**拒绝（不会做了一半），刷新后重试即可。

## 数据与同步

正文快照、移出活动章节和原有记忆失效在一个 SQLite 事务内完成。还原也将旧目标归档、新正文和新的 canonical commit 一并写入；任一写入失败会整体回滚。

回收正文不再用于活动章节列表、检索或已有来源标记的事实、实体与状态。还原后通过确定性投影同步摘要、检索、记忆和剧情状态，不调用模型。同步失败不撤回已还原的正文，章节记忆面板保留待同步记录。

旧版本的 Story State 没有完整的修改前快照，混合多章且缺失来源的人工历史内容无法可靠反推。本功能按记录的章节来源撤销派生信息，并保留作者基础设定；以后新状态转换保存修改前快照。不会为了清理记忆重置全书状态。

此前已经物理删除且没有备份的正文无法补救。本功能上线前被旧大纲隐藏但仍在数据库中的章节不会在启动时擅自迁移。系统备份独立保留，不会因回收站永久删除而改写已有备份。

## 权限和成本

所有回收站接口要求项目 owner；目标章节必须在当前项目大纲中，不能使用跨项目资源 ID。所有回收、预览、还原和清理操作均为本地数据操作，真实 LLM 调用为 0。
