# 大纲与正文助手
更新：2026-09-21。章节导航按总纲、卷、剧情弧、章节组成；剧情弧是可变章数的小故事，不应给每卷机械复制一条主线弧模板。

导入的 Markdown 作品会**按章节自动生成一层平铺大纲**（每章一个 `chapter` 节点，不虚构卷、弧或摘要），所以导入后章节导航立刻有内容。它不经过模型；要更细的结构再用下面的指令生成候选。

## 指令与候选
- 普通咨询：解释/建议，不改写作品。
- 调整大纲：说明目标卷/弧和调整方向，返回结构化候选及 Diff。
- 调整正文：以当前章节和大纲目标为范围，返回正文修改候选；不把“改正文”误当大纲编辑。

候选出现在相关会话中，确认前服务器原大纲/正文不变。应用后重载项目，章节导航使用新的结构。拒绝不修改原作。移除已有正文章节属于额外确认，候选应同时显示其他实际修改，不能仅显示删除警告。

## 正文保护与回收
大纲调整导致整章移除时，作者确认后正文进入[回收站](chapter-recycle-bin.md)，可还原到当前大纲的指定章节；不是自动物理删除。跨项目ID、错属节点和真实版本冲突仍不能靠聊天绕过。应用期间若大纲/正文已改变，先核对最新版本，不能用旧候选强制覆盖。

## 上下文与模型策略
编辑请求携带总纲、卷、弧与目标章节范围，服务器保存完整大纲用于合并/校验。200章项目不应反复把全部章节和完整聊天历史塞入请求。过宽请求在调用前拒绝；反复重试同一超限输入不能解决问题。

Planning 保留 thinking；Writing/Copilot 默认 disabled。实际 Arts 请求应遵从角色策略，模型/温度/token上限仍以最终配置为准。当前有目标弧约束回归，**未证明真实模型永远不提前暗示后续剧情**；应保留小规模人工验收边界，不以模板式本地结果替代成功。

## 失败反馈
- llm：模型返回；仍需区分“返回”与“候选合法/已应用”。
- fallback：本地建议，不是真实模型结果，不自动生成可应用候选。
- failed：失败，保留原作，展示安全原因和 trace/诊断编号。

后处理审计按 json_extract、normalize、merge、validate、candidate_create 定位；只保留结构类型、数量、状态和错误码，不记录完整模型回复/Prompt/密钥。诊断时记录编号、目标章/弧、候选状态和发生步骤，不上传密钥。

真实调用只在限定授权和预算下进行。模型已返回但校验失败也可能计费；不自动 retry 或让另一个模型修JSON。刷新/重新打开读取状态；“重新生成”是用户发起的新请求。
